## Measure (once per device)

- [ ] Record the CSS viewport width and height in Safari, portrait and landscape (the device size derivation in the [device specs](../research/v2.0-apple-device-specs.md) is unconfirmed).
- [ ] Record the viewport again as a home-screen app.

## Run each time

Run in Safari and as a home-screen app, in light and dark.

- [ ] Navigation: tabs, the icon rail or Sidebar at the right width, avatar opens Settings, Back and Forward.
- [ ] Safe areas: nothing hidden behind the Dynamic Island, status bar or home indicator; tab bar clears the home indicator.
- [ ] Keyboard and focus: fields stay visible with the keyboard open; focus order is sensible.
- [ ] Dark mode: follows the system; Appearance control (System, Light, Dark) overrides it; no flash on load.
- [ ] Orientation: iPad rotates and both layouts work; iPhone behavior is as documented (portrait only).
- [ ] Add to home screen: icon, name, launch with no browser chrome, status bar and theme color.
- [ ] Camera (v1.6.2): barcode scan permission, preview and entry.
- [ ] Voice entry, if enabled: microphone permission and review flow.
- [ ] VoiceOver basics: tabs, headings, the Shop selector and a sheet announce and navigate sensibly.
- [ ] Text size: larger system text does not clip controls.

## M4-9 baseline (before any manifest, icon or theme-color change)

[M4 decision 12](../specs/v2.0-m4-screen-redesign.md) changes the PWA settings only after they are confirmed on a device. Before M4-9 changes anything, look at what the *current* build does, so each change is made for something seen and not for something assumed. Use the Vercel Preview of the M4-9 baseline PR (the app as it is on `develop`: the same manifest, icon, orientation and theme color as `main`, with the M4 shell). Delete any older PantryBot home-screen icon first: iOS keeps the icon and name it saw when the page was added.

Record what you see in the Result column; a photo helps for the colors and the icon. "Same as expected" is a result too.

| # | Device | What to do | What to record | Result |
|---|---|---|---|---|
| O1 | iPad | Add to Home Screen, open it from the home screen, rotate to landscape and back. | Does the app rotate? Does the layout change (icon rail or Sidebar in landscape, tab bar in portrait)? Or does it stay portrait? (The manifest says `portrait-primary`.) | |
| O2 | iPhone | Same as O1. | Does the home-screen app stay portrait when you rotate? | |
| O3 | iPhone and iPad | After Add to Home Screen, look at the icon on the home screen and in the App Switcher. | Which icon shows: the emerald Dutch oven, a screenshot-like tile, a letter on a plain tile, or something else? Is the name "PantryBot"? | |
| O4 | iPhone and iPad | In Safari (not the home-screen app), open the Preview in light, then in dark (system setting). | What color is the area around the status bar and the tab strip? Does it follow light and dark, or stay one color (the current `theme-color` is emerald, `#059669`)? | |
| O5 | iPhone and iPad | In the home-screen app, light and dark. | Is the status bar text readable over the app header? Is anything cut off under the Dynamic Island or status bar? | |
| O6 | iPhone and iPad | Close the home-screen app and open it again. | What does the launch screen look like before the app appears (white, black, a dark navy, the icon)? Does it flash the wrong color in light or dark? | |
| O7 | iPhone | Set the system to Light, then Settings, Appearance, Dark in the app. In Safari, then in the home-screen app. | Does the browser or status bar tint change when the in-app Appearance changes? | |
| O8 | Both | Settings, About, a quick look. | The iOS or iPadOS version of each device (also fill in the Devices table above). | |

What each answer decides:

- **O1 and O2** decide whether `orientation` changes: if the iPad home-screen app is stuck in portrait, `portrait-primary` goes (the iPhone's portrait-only rule is kept by the layout, not the manifest). If it already rotates, nothing changes.
- **O3** decides whether PNG icons are added (a 180 px `apple-touch-icon`, plus 192 and 512 manifest icons, the 512 one with a maskable safe zone).
- **O4, O5, O6 and O7** decide the theme-color and manifest-color change (one `theme-color` per light and dark scheme from the tokens, kept in step with the in-app Appearance, and manifest colors on the token surface).
