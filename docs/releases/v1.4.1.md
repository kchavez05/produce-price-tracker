# v1.4.1 — Price Freshness and Sync Reliability

Prepared October 27, 2026. Production publication is pending release approval.

## Weekly prices and automation

- The planning cycle now advances on Wednesdays in America/Denver, including daylight saving changes.
- Expired, future and undated circulars are excluded. Exact source expiration timestamps are preserved; Kroger prices are identified as same-day observations.
- Verified prices take priority over historical estimates. The checklist, single-store recommendations and two-store optimizer consistently prioritize live coverage.
- Missing coverage remains usable without API keys, with explicit estimate labels and no unsupported stock-up or freezer-savings alerts.
- Refresh attempts, live retrievals and page generation have separate timestamps. Source status and actual usable offer counts replace synthetic sync counts.
- Live history is saved under the current ad week; six-week statistics exclude older and future rows.
- Scheduled GET requests require CRON_SECRET bearer authentication. Manual refreshes are same-origin and rate limited.
- Optional Supabase audit records persist sync outcomes across serverless instances. Failed durable writes produce a visible error rather than a successful audit acknowledgment.

## Account and cloud-sync reliability

This release also promotes the previously reviewed develop changes for session isolation and reliable cloud sync (#554): verified session ownership, private guest state, account-bound pending writes, retry-safe replay, and preservation of local edits during cloud failures. See docs/security-sync-remediation.md for details.

Repository maintenance includes security documentation and explicit CI permissions (#553), Dependabot branch policies (#552, #558), and the lucide-react dependency update (#549).

## Configuration and database

The existing PantryBot Supabase project has the additive weekly_refresh_audit migration applied, with RLS enabled and browser-role access revoked. Production and preview have separate CRON_SECRET values. SUPABASE_SECRET_KEY remains server-only and is optional for local use. Flipp requires no key; USDA and Kroger credentials are optional and are not required for these fixes.

Preview environments use local audit storage unless a server-only audit key is configured. Local SQLite may be ephemeral on Vercel. The API explicitly distinguishes cloud, local and unavailable audit storage.

## Validation

Typecheck, lint, 82 unit tests, 11 smoke tests, 32 regression tests, and the production build pass. Added tests cover Mountain Time/DST rollover, exact expiry boundaries, partial feed failures, offline estimates, cart optimizer consistency, durable audit failures and restoration, cron authentication, and rolling six-week history.

Protected preview checks confirmed the current planning cycle, live Flipp retrieval, manual sync success, and HTTP 401 for a forged cron header. Release gates require successful CI, Vercel deployment, completed Codex review and resolved actionable findings.

## Operational limits

Historical estimates and wholesale baselines are planning aids; verify final prices with the retailer. Runtime log retention could not establish whether last week's jobs ran. The deployment verification confirms the current configuration and manual ingestion path; the next natural scheduled execution remains a future event.
