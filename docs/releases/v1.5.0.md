# v1.5.0 — Weekly USDA and durable market history

Retrospective record (November 11, 2026): [closed milestone v1.5.0](https://github.com/kchavez05/produce-price-tracker/milestone/12); original [GitHub publication](https://github.com/kchavez05/produce-price-tracker/releases/tag/v1.5.0) dated 2026-10-28 (America/Denver). See the [release audit](retrospective-audit-2026-11-11.md#v150) for verified gates, gaps and follow-ups. Earlier preparation steps below remain historical context.

PantryBot now separates scheduled USDA ingestion from ordinary application use. One authenticated Wednesday batch preserves complete reports and compatible normalized retail benchmarks in Supabase; dashboards, Friday digests and manual grocery refreshes reuse stored data without USDA requests.

## Delivered

- Validated five USDA retail report sources and exact commodity/unit mappings. Current sources provide national values, clearly labeled; the previous Mountain-region assumption was incorrect.
- Immutable source versions, observations, catalog revisions and publication history, with durable cycle claims, worker fencing, bounded retries and transactional publication.
- Shared Flipp/Kroger price history in Supabase with immutable price revisions, retrieval receipts, and bounded six-week reads. Failed archives return an explicit error and can be retried.
- Historical backfill and recovery commands, source-period freshness, fourteen-day maximum scoring age, null gaps, and quarantined legacy seed data.
- Weekly ingestion health checks through GitHub Actions, without giving CI a USDA key.
- Recipe rotation: retain the strongest value match and rotate the other two slots each Mountain Wednesday when enough recipes fit the user's profile.

## Configuration and operational decisions

Follow [the complete market-data runbook](../usda-market-data.md). Apply the additive market-history migration and validate the report definitions before enabling ingestion. USDA_MARS_API_KEY and USDA_INGEST_ENABLED belong only in Vercel production; SUPABASE_SECRET_KEY and CRON_SECRET remain server-only.

Keep Wednesday 13:00 UTC. Latest validated reports were published Friday, so Wednesday uses the latest available release rather than promising new reports every Wednesday. Source publication clock strings have no timezone offset and are preserved without inventing one. Historical source periods, retrieval times and planning cycles remain separate.

SQLite seed rows are not authentic historical observations. Their import is quarantined and excluded from verified history; guest-session SQLite behavior is retained. Missing cloud history never falls back to synthetic series labeled as verified.

## Validation and release gate

Run typecheck, lint, unit, smoke, regression and production build checks, including embedded Postgres migration/permissions/rollback tests and real source excerpts. Require passing CI, Vercel build and completed Codex review before merging. Verify a controlled ingestion, duplicate-run safety, cloud price archival and dashboard provenance after activation. The next scheduled Wednesday execution must still be observed; manual verification does not prove a future schedule ran.
