## Changes

- [#749](https://github.com/kchavez05/produce-price-tracker/issues/749): provider-neutral recipe generation uses application-owned prompts, schema/catalog validation, servings, IDs and authoritative pricing. Generated output never updates pantry inventory.
- [#751](https://github.com/kchavez05/produce-price-tracker/issues/751): app-funded AI requires a freshly verified signed-in account. Personal API keys are retired. Guests retain deterministic standard suggestions and manual pantry entry. Requests and results remain bound to the account that started them; client-supplied ownership cannot authorize paid work.
- [#752](https://github.com/kchavez05/produce-price-tracker/issues/752): provisional recipes use GPT-6.1 Terra; speech uses GPT-Transcribe → GPT-6 Luna. Complete-input token preflight, bounded audio/output, deadlines, Standard tier, explicit 30-minute cache lifetime and one attempt per stage constrain exposure. No automatic retry or provider failover.
- [#664](https://github.com/kchavez05/produce-price-tracker/issues/664): durable admission reserves exposure before dispatch across instances. Combined ceilings are $5 per verified account/day and $20 shared/month, UTC, with one active request per account. Full fixed reservations are retained on failure/cancellation; completion releases concurrency only. Duplicate request IDs cannot replay paid work. A shared operator kill switch preserves manual alternatives.
- [#753](https://github.com/kchavez05/produce-price-tracker/issues/753): **experimental speech entry** records up to 30 seconds, then proposes pantry ingredients for editable review and explicit confirmation. Recording/transcription never saves inventory automatically. Account changes/cancellation discard stale work; confirmation uses existing owner-bound, repeat-safe pantry operations.

## Data treatment and upgrade behavior

Both integrations use the server `OPENAI_API_KEY`; never expose it or `SUPABASE_SECRET_KEY` in public environment variables. The app does not persist raw audio/transcripts; only explicit pantry confirmations use normal storage. The ledger contains ownership/request identifiers and usage metadata, not prompts, recordings or model outputs. OpenAI processes submitted audio/text under the disclosed provider terms; `store:false` does not establish Zero Data Retention. See the privacy page and [qualification evidence](../research/v1.7-provider-qualification.md).

Older clients sending `geminiApiKey` receive `CLIENT_UPDATE_REQUIRED`; reload instead of submitting a personal key. Existing pantry, saved recipes and sync ownership remain intact. No subscription/paywall or automatic inventory addition is introduced.
