Owner inclusion: November 14, 2026. Parent #748; model-independent work authorized while #731 is in review. Billing and provider activation remain separate gates.

Capture uses explicit browser microphone permission in a secure context, mono PCM capture in an AudioWorklet, bounded to 30 seconds. Stop ends tracks immediately and creates a canonical 16 kHz, mono, signed 16-bit WAV in memory; cancellation/account change/unmount discard it. Permission resolution after cancellation must stop the late stream. Unsupported/offline/denied capture keeps ordinary manual pantry entry usable. No automatic recording or background microphone.

The server accepts only a bounded canonical WAV (44-byte header, PCM16 mono 16 kHz, 0.25–30 seconds) and a request UUID, not caller ownership. Header fields and actual data length must agree. It verifies the current account before any dispatch, then reserves the complete transcription-plus-extraction bound through #664. The provider-independent contracts expose transcription and extraction separately; the selected factory uses GPT-Transcribe → GPT-6 Luna, while paid dispatch remains disabled until #752 verifies the exact endpoints/combined bound and the operator registers it in the durable ledger. Each stage makes one attempt within a shared 60-second deadline. No partial-stage automatic retries or refunds.

Extraction receives a bounded transcript as untrusted data plus the exact pantry cooking catalog. Return only a review draft: PROPOSALS, NO_ADD or UNCLEAR. Negation/corrections must not invent additions, quantities or units. Unknown forms remain custom or explicitly unresolved; no fuzzy or broad market-ID substitution. Local validation bounds arrays, text and numeric fields and rejects unknown IDs. Nothing in this endpoint reads or mutates inventory.

The UI shows the transcript and every proposed ingredient/form/quantity/unit. Users can remove rows, correct quantities/units, choose an exact available catalog identity or keep an explicitly named custom ingredient. Existing optional pantry details are preserved by default and visible in the review; accepting a spoken replacement quantity must be explicit. A frozen confirmation snapshot captures entry IDs, revisions and mutation UUIDs. Confirming uses the existing owner-bound, revision-aware pantry save queue. Repeated confirmation reuses the same intent and cannot duplicate additions. Partial failure retains the same frozen operations for retry; completed rows are not submitted again. Owner changes invalidate capture, responses and review before any further save.

Raw audio/transcript/output exist only in request/component memory and are never logged or stored in the usage ledger/browser storage. Confirmed pantry entries persist through the ordinary pantry contract. Provider endpoint retention/disclosure and actual-browser/device microphone/quality verification are #752/#750 release gates; synthetic tests cannot establish those facts.

Owner launch policy was clarified during implementation: $5 per account/day and $20 shared/month (UTC), combining both pipeline stages with recipes. The optional count cap remains zero; dollar/concurrency enforcement is mandatory. The policy stays disabled until provider-bound and hosted acceptance gates pass.

Browser API references: [AudioWorklet](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet) requires a secure context. Capture releases every acquired track with [MediaStreamTrack.stop](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/stop); another tab may still own its own microphone track. These API checks do not establish real-device audio quality.
