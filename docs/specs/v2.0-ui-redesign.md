# v2.0 UI Redesign — Draft Specification

Status: **Draft — planning only.** Not approved. Starts after v1.6.2 and v1.7.

## 1. Purpose

Replace the current UI with a maintainable, accessible, responsive design system while leaving product behavior (pricing, scoring, sync, session ownership, zero-key fallbacks) unchanged.

## 2. Current state (as of v1.6.1)

- Next.js 15 (App Router), React 19, Tailwind v4; `lucide-react` is the only UI dependency.
- No design tokens (two CSS variables in `src/app/globals.css`), no dark mode, no i18n.
- `src/components/MealPrepDashboard.tsx` (~4,100 lines) holds nearly all UI at `/`; `explorer/DataExplorer.tsx` (~1,400) and `AccountModal.tsx` (~550) are the next largest.
- UI routes: `/`, `/data`, `/docs`, `/api-docs`, `/privacy`, `/terms`; `/auth/callback` is route-only.
- Tests are Vitest. Logic tests are the bulk; jsdom component tests exist for `VirtualPantry`, `BarcodeEntry` and `BarcodeCamera`, hand-rolled with `react-dom/client` and `act` (no React Testing Library). There are no tests for `MealPrepDashboard`, `AccountModal` or the Data Explorer, and no browser, visual or accessibility tests.

## 3. Goals

Primary goal: **split the monolithic homepage into separate workflow modules.** Virtual Pantry is currently stacked on the main view; it becomes its own destination.

Modules (working names):

1. **Shop** — price and shopping optimization.
2. **Pantry** — inventory management (Virtual Pantry).
3. **Plan** — meal-prep planning, consuming Shop and Pantry data plus user preferences.

Supporting goals:

- **Mobile-first**, touch-first design; desktop web is lowest priority.
- **First step toward native apps** (v2.x): navigation, tokens and module boundaries should map cleanly to Expo/React Native so web and native feel like one product.
- Navigation follows Apple conventions: bottom tab bar on iPhone, sidebar on iPad.
- Foundations: design tokens, dark mode, accessibility (WCAG AA).

## 3a. Target devices (Apple ecosystem first)

- iPhone and iPad, latest models, touch-first. Delivered as the web app/PWA in v2.0; native follows in v2.x. Android and desktop web follow later.
- Current lineup per Apple's site (checked November 2026; verify specs before locking layouts): iPhone Duo (foldable; 7.6-inch inner and 5.4-inch outer display, iOS 27), iPad Pro 11/13 (M5), iPad Air 11/13 (M4), iPad (A16, 11-inch) and iPad mini (A20 Pro, about 8.3-8.5 inch).
- **iPhone is portrait-only for v2.0** (owner decision, 2026-11-12). No iPhone landscape layout is designed or tested; the web fallback keeps the compact layout at short viewport heights. See [Apple device specs](../research/v2.0-apple-device-specs.md).
- Design for iPhone and iPad size classes (compact/regular width) rather than specific models, so iPhone Duo's two displays and iPad mini are covered by the same responsive rules.
- iPhone Duo-specific posture handling (Split View, folded/unfolded transitions) is **deferred** unless it proves cheap; iPad mini and iPad layouts are in scope.

## 3b. Features that must be incorporated

The redesign covers everything shipped through v1.7, not just today's screens. Detailed UI for these is specified in their own specs; v2.0 owns where they live and how they look.

- **Barcode scanning (v1.6.2):** typed and camera entry with mapping to generic ingredients and user confirmation/correction (Pantry).
- **Dynamic pantry-staple pricing (v1.6.2):** replaces fixed estimates (Pantry, Shop, Plan cost displays).
- **Speech-to-inventory (version unassigned, before v1.7):** dictate, review/correct, explicitly confirm (Pantry).
- **v1.7 sign-in for AI features:** the bring-your-own-key input is removed; guests see a "Sign in to access AI features" action; AI states and recoverable service errors (Plan's AI chef, speech).
- Any further feature that lands before v2.0 begins is added here when it ships.

## 4. Non-goals

- Changes to sync queues, session ownership, auth, pricing or scoring logic.
- New required environment variables or API keys.
- Billing, paywalls, or building the native apps (v2.x).
- Expanding the shopping list feature (v2.0 only relocates it; enhancements are separate future scope).

## 6. Guardrails

- Zero-key offline behavior preserved; deterministic fallbacks intact.
- Strict TypeScript, no `any`, no `eslint-disable` masking stale closures.
- Client components declare `'use client'`; `localStorage` reads are hydration-safe.
- Any required change under `src/hooks` or `src/lib` sync/ownership code ships as a separate, reviewed PR.

## 6a. Design conventions

- **Title Case headings.** Headings, section labels and card titles use title case ("Stocked Up From Deals"). Buttons, chips and body copy use sentence case.
- **No redundant screen titles.** On the three tab screens (Shop, Pantry, Plan) the selected tab already names the screen, so no visible page title repeats it. Each screen keeps a visually hidden `h1` with its name for screen readers and heading navigation. Screens that are not tabs (for example Account and Settings) keep a visible title.
- **Touch targets** are at least 44px in both dimensions, including chips and icon buttons.
- **No required Pantry input.** Pantry-aware features never block or nag; see the flows document, section 2a.

## 7. Design review process (M0)

Mockups are approved before implementation: brief, flows and wireframes per module, clickable high-fidelity HTML mockups at iPhone and iPad sizes, review rounds with comments on specific screens, then lock and extract tokens and a component list.
