# v2.0 M1: Foundations — Draft Plan

Status: **Draft — planning only; not approved.** Part of the [v2.0 specification](./v2.0-ui-redesign.md). Tracked in [#685](https://github.com/kchavez05/produce-price-tracker/issues/685), under the v2.0.0 release parent [#682](https://github.com/kchavez05/produce-price-tracker/issues/682).

## 1. Purpose and scope

Give the app a design foundation that web uses now and the native apps (v2.x) can reuse: design tokens, light and dark themes, and a small set of accessible UI primitives. M1 changes no screens. It does not decompose the dashboard (M3), redesign screens (M4) or build the browser test stack (M2).

## 2. Baseline (develop at `8ad453a`, surveyed 2026-11-12)

- Tailwind 4.3.5 through `@tailwindcss/postcss`; `src/app/globals.css` is 42 lines with two CSS variables, a `.pantry-select` class, a forced-colors fallback and print rules. No `@theme`, no `@custom-variant`, no `dark:` classes.
- About 1,000 hardcoded palette utility classes (`bg-slate-*`, `text-emerald-*`, and so on): `MealPrepDashboard.tsx` 689, `AccountModal.tsx` 115, `privacy` 37, `SwaggerUIConsole.tsx` 35, `VirtualPantry.tsx` 33, `terms` 30, `AppFooter.tsx` 24, `docs` 20, `BarcodeEntry.tsx` 8. No arbitrary hex values and only three gradient uses.
- The Data Explorer is styled separately by `src/app/data/explorer.css` (473 lines, its own `--ink`, `--muted`, `--line`, `--paper` variables, 43 hex values) and has no dark theme.
- Hand-styled controls: 115 `<button>`, 15 `<select>`, 22 `<input>`; no `<dialog>`, `role="dialog"` or `aria-modal` anywhere.
- System font stack, no `next/font`. `lucide-react` 1.70.0 is the only UI dependency. Manifest `theme_color` is `#059669` and `background_color` is `#0f172a`.

## 3. Token architecture

- **Layers:** a raw palette (scales), then **semantic tokens** (surface, surface-raised, text, text-muted, border, accent, success, warning, danger, focus ring, overlay), then component tokens only where needed. Components use semantic tokens only.
- **Other scales:** radius (control, card, pill), type (title, heading, body, caption), elevation, motion (honoring `prefers-reduced-motion`), and a `touch` size of 44px.
- **Tailwind 4 wiring:** semantic names exposed through `@theme` so utilities read `bg-surface` and `text-muted`, with values switched by theme variables.
- **Source of truth (recommended):** a typed `src/design/tokens.ts` with no new dependency, and a generator that writes `tokens.css`, checked in CI with a `--check` mode like the existing `catalog:build --check`. Numbers, not web-only units, so a React Native theme can be generated from the same file in v2.1.
- **Values:** structure can proceed now; actual colors, type and density wait on the visual-direction decision (open).

## 4. Dark mode

- Default follows the system (`prefers-color-scheme`); Settings offers System, Light and Dark, stored on the device.
- Avoid a flash and hydration mismatches (a `docs/code-review.md` rule): a small blocking script in `<head>` sets `data-theme` before paint and `<html>` carries `suppressHydrationWarning`; React reads the stored value only after mount.
- Set `color-scheme`, per-scheme `themeColor`, and keep print light and forced-colors working.
- **Contrast is tested:** a Tier 1 unit test computes ratios for every semantic text/surface and UI/surface pair from `tokens.ts` (text at least 4.5:1, UI components at least 3:1) in both themes.

## 5. Primitives (initial set, in `src/components/ui/`)

Button (primary, secondary, quiet, destructive text, loading), IconButton (accessible name required), TextField, Select, Checkbox, SegmentedControl, Chip, Card, Badge, Banner (info, warning, error with `role="alert"`), Sheet/Dialog (focus trap, Escape, return focus, `aria-modal`), TabBar and Sidebar navigation, ListRow, EmptyState, Skeleton, VisuallyHidden, PageHeader.

Rules: strict TypeScript with no `any`, ref forwarding, 44px minimum targets, visible focus, keyboard operable, Title Case headings per spec section 6a.

## 6. Migration strategy

- **Additive, no big bang.** M1 lands tokens, themes and primitives without changing screens. M3 and M4 consume them.
- **Existing classes keep working.** Slate and emerald utilities stay until the screens move in M4.
- **Ratchet guard.** A CI check records today's count of raw palette classes per file and fails if it grows, so new code uses tokens and the count only falls.
- **Explorer CSS** maps its four variables onto tokens in M4.
- **Living style guide:** a development-only `/design` route showing tokens and primitives (hidden in production), instead of adding Storybook now.

## 7. Proposed work breakdown (each a normal PR)

1. Tokens: `tokens.ts`, generator, `tokens.css`, Tailwind `@theme`, contrast test.
2. Theme switching: head script, Settings control hook, `color-scheme` and `themeColor`, print and forced-colors checks.
3. Primitives batch 1: Button, IconButton, TextField, Select, Checkbox, SegmentedControl, Chip.
4. Primitives batch 2: Card, Badge, Banner, Sheet/Dialog, TabBar, Sidebar, ListRow, EmptyState, Skeleton.
5. Style guide route, ratchet guard and documentation (wiki design-system page, code-review notes).

## 8. Proposed acceptance criteria

- Semantic tokens and generator in place; `--check` passes in CI; no new runtime dependency unless approved.
- Light and dark themes pass the contrast test; System, Light and Dark selectable and remembered; no flash on load and no hydration warnings.
- Every primitive has typed props, keyboard and screen-reader behavior verified by tests, and a style guide entry.
- The ratchet guard is enforced in CI.
- No change to sync, auth, pricing, scoring or zero-key behavior; existing screens render unchanged.

## 9. Risks

- Visual regressions in unchanged screens: mitigated by not touching screens and by the component test harness (see decision 1).
- Tailwind 4 specifics (`@theme` naming, dark variant strategy) and Next 15 `themeColor` handling need a short spike.
- Scope creep into restyling screens: out of scope until M4.

## 10. Dependencies and open decisions

1. **Test harness timing.** Primitives need component and accessibility tests, but test infrastructure is M2. Recommend pulling the minimal jsdom, React Testing Library and axe harness forward into M1 (browser smoke and visual checks stay in M2), or doing M2 first.
2. **Visual direction** (colors, type, radius, density): needed for token values; structure and generator can start without it.
3. **Headless primitives vs hand-built.** Default: hand-built with tests; alternative: one headless dependency for dialog and focus handling only. Needs approval before adding a dependency.
4. **Token location.** `src/design/tokens.ts` now, extracted to a shared package at the v2.1 monorepo step (recommended), or a package from the start.
5. **Timing.** M1 touches only `globals.css`, the root layout, a new `design` folder and new components, so it could start before v1.7 ships with little conflict risk. The release parent currently says implementation waits for v1.6.2 and v1.7; owner's call.
6. **Style guide.** Development-only `/design` route (recommended) or Storybook in M2.
