# v1.6.2 pure staple pricing evaluator foundation

The maintainer approved PQ-01–08 after reviewing the qualification packet in chat on November 9, 2026. The [decision record](../../catalog/proposals/2026-11-09-staple-pricing-qualification/decision-record.json) binds the original packet digest without rewriting the reviewed payloads. Provider unconditional/USD semantics and use/retention rights remain unresolved. This implementation creates no live source adapter, active source contract, runtime product admissions, public endpoint, storage or feature activation.

`src/lib/pantry/price-evaluator.ts` is a pure internal costing component. It consumes already resolved boolean pantry ownership, stable recipe requirement keys, reviewed package/form admission records, source quotes, source gates and existing reviewed static prices. Server-side integration must own those inputs; caller-supplied flags or product choices cannot establish permissions, food evidence or ownership. The module has no network, browser, account, storage or catalog mutation dependencies.

It implements same-dimension exact rational costing, scoped source-size/revision admission, regular Production price qualification, selected-market/location and Mountain-day freshness, effective/expiry checks, stock qualification, source revision deduplication/conflicts, exact-cost selection and deterministic cent reconciliation. The newest unavailable/unqualified snapshot shadows older prices rather than resurrecting one. Two admitted ingredient identities may use the same physical product quote while retaining independent pantry ownership.

Observed pricing fails closed unless explicitly enabled with both verified source gates and a matching source-contract version. No such real contract is provided here. Missing evidence falls through to an existing exact-unit static price, then unpriced; no replacement static prices are introduced. Yes and optional rows contribute no additional need. Unknown prices remain null, not zero. A zero-price observation requires explicit source evidence. Invalid clocks, duplicate requirement keys, excessive workloads and aggregate overflow fail explicitly.

The evaluator returns allocated integer cents, basis and quote/rule references. It rounds the exact staple total once, distributes display cents by largest remainder and stable requirement keys, and preserves input order. Adding preexisting integer market-slot cents preserves that rounding boundary. Integration must reuse these authoritative rows in shopping rather than independently rounding them again. Existing recipe, saved-recipe and shopping functions remain unchanged in this foundation PR; their shared-context wiring is the next implementation step.

The normalized package amount/unit comes from the reviewed admission record, not fuzzy parsing or a caller's scan. A raw source label must match that record and product revision exactly. Generic `fo`, bare-oz volume, density, drained-yield, serving-count and food-component inference are absent. Date-only validity is not accepted by this component; a future source adapter must apply a documented timezone before providing an instant. No Kroger response payloads or actual quotes were added as fixtures.

Focused synthetic tests exercise the eight arithmetic vectors from the packet and source-gate, expiry/midnight, unit/form/basis, revision replay/conflict, deterministic selection, overflow, fallback, rounding, ownership and immutability boundaries. This is not a claim that all 50 broader acceptance vectors, source operations, UI presentation, source retention or deployed flows are implemented. The server adapter and end-to-end current/saved/shopping integration still require separate verification.

Local validation: catalog projection, typecheck, lint, 877 unit tests (including 69 evaluator cases), 28 smoke tests, 37 regression tests, production build and critical dependency audit pass. The original qualification envelope hashes remain intact. No real source contract is approved or enabled by passing these checks.
