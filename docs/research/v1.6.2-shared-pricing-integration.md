# v1.6.2 shared recipe pricing integration

Current scope: the November 12 [approved amendment](v1.6.2-static-pricing-scope-amendment.md) makes static/unpriced staple estimates the MVP deliverable and moves new live store API work to #689. The implementation and validation receipt below is retained as historical evidence; its future-source requirements are no longer v1.6.2 release gates. Existing market-discovery behavior is preserved.

Current recipes, saved-recipe reevaluation and shopping now use the pure evaluator through an internal immutable price context. This continues the [approved qualification packet](v1.6.2-pricing-qualification-packet.md). It does not activate live staple pricing or complete the barcode milestone.

## Implemented behavior

- A request/render snapshot supplies evaluation time, market, selected locations, source permissions, admissions and quotes. The adapter supplies static prices exclusively from the reviewed pantry catalog. HTTP callers cannot supply a price context or source permission. The default has no live source, permissions, admissions or quotes.
- Recipe rows carry their allocated cents and price basis: observed, static estimate, unpriced, on hand or optional. Static and incomplete flags remain independent. Observed details include source location, observation time, package price/amount/unit, source label, admission revision and stock uncertainty.
- Shopping reevaluates requirements against the current context, then sums recipe allocations. It groups display quantities without repricing or rounding the combined quantity. Unpriced quantities remain visible beside the known subtotal. It rejects Kroger staple observations if King Soopers leaves the selected shopping store pool.
- Current ranking and saved reevaluation use the same context. Serving, pantry Yes/No, pinned-alternative and dietary changes derive requirements again. Saved recipes retain their explicit requirements, including any reviewed quantity basis; stale displayed prices never establish current eligibility.
- The five reviewed canned built-in requirements explicitly carry `canned-net-contents-v1`. This denotes labeled unopened can contents, not drained food mass. Missing metadata on an older saved requirement is never inferred or upgraded during reevaluation.
- Recipe and shopping displays, clipboard labels and response OpenAPI distinguish the price basis and explain that recipe use differs from package checkout cost. The dashboard shares one context across ranking, custom recipes and shopping, refreshing its clock on focus and every minute. Because the shipped context has no observed data, this clock never extends live quote validity.
- Saving removes the new derived `pantryPricing` field before client state and owner-scoped SQLite persistence. Cloud synchronization consumes those cleaned saved recipes. Existing recipe amounts, ownership, authentication, cloud retries and schema remain unchanged. Merely reevaluating a saved recipe does not write it back.

## Verification and remaining work

Synthetic tests cover current/saved/shopping agreement, per-recipe rounding, serving changes, pinned and dietary selection, explicit Yes/No, expiry and Mountain midnight, market/store/rule changes, disable behavior, mixed labels, partial totals, stale canned basis and immutable contexts. An isolated SQLite test verifies derived evidence is absent from stored JSON and recipes stay private to their owner. Source fixtures are synthetic; this change adds no real quote payloads or persisted source cache.

Live provider activation remains disabled. Before adding a real adapter, resolve unconditional USD price semantics and permitted use/retention; review actual product admissions and source diagnostics, enforce the shared request budget/rate limits, and implement exact expiry/day invalidation for delivered observations. A minute-based UI clock alone is not sufficient for future observed-price activation. Barcode lookup and camera support remain separate work.

Local checks: typecheck, lint, 901 unit tests, 28 smoke tests, 37 regression tests, production build and catalog projection check pass. OpenAPI exports are synchronized. CI/Preview and a completed latest-head Copilot review remain merge gates.

Copilot follow-up: numeric recipe quantities preserve their full decimal representation, including exponent notation, while source package precision stays bounded separately. Checklist labels distinguish versioned unopened-can contents from an older saved quantity with no recorded basis, preventing Set/checkbox collisions. Five additional regression vectors cover these findings.

Saved serving scaling also retains full numeric precision until the evaluator allocates cents. An unchanged-servings regression verifies that a 2.02499 tbsp requirement retains its $0.40 static allocation rather than being rounded up to $0.41.
