## Hosted privileges and admission behavior

All five `ai_private` tables have RLS enabled. `anon` and `authenticated` have neither schema USAGE nor SELECT and cannot execute either RPC. `service_role` can execute both RPCs and update usage/reservations, but cannot update policy or adapter registrations. Actual role-switched calls confirmed the denials; these are not inferred from a green migration alone.

The reproducible [rollback checks](v1.7-hosted-ai-usage/rollback-checks.sql) pass on the deployed functions. They fail closed unless the initial policy is disabled and there are no existing adapters/reservations/usage rows. They create five synthetic Auth users and trigger-created profiles **only within a deliberately rolled-back subtransaction**. Temporary test-only policy/adapter rows are never committed or visible to independent requests. The script calls database RPCs only, never any model endpoint or pantry mutation API.

Checks cover:

- Disabled policy, wrong adapter and mismatched cost bound deny admission.
- An admitted reservation has the expected remaining daily dollars; zero action cap means no additional count cap.
- Duplicate request IDs do not replay, account concurrency blocks a second request, and another account cannot complete a reservation.
- Repeat completion is safe and releases concurrency without refunding reserved exposure.
- Recipe and speech share daily actions/dollars; both count and dollar exhaustion work.
- A ten-request sequential burst admits exactly two 100-micro-USD reservations against 200 micro-USD remaining monthly capacity; the other eight are denied.
- Deleting a synthetic account cascades its personal usage rows while preserving aggregate monthly exposure.
- An expired concurrency lease permits progress while retaining the prior reservation's cost.
- A synthetic prior-day usage row does not consume today's UTC allowance.
- The disable switch stops admission, and service-role attempts to update policy/adapter limits are denied.
- Guest and authenticated roles cannot read private tables or invoke admission.
- Rollback removes all synthetic Auth users, profiles, preferences, adapters and usage rows, and restores the disabled $5/day / $20/month policy.

The real application service-role Supabase HTTP client independently returned `{allowed:false, reason:"DISABLED"}` without a reservation.
