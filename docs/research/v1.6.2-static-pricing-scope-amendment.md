# v1.6.2 MVP static-pricing scope amendment

Approved by the maintainer in chat on November 12, 2026. Tracked by [release parent #645](https://github.com/kchavez05/produce-price-tracker/issues/645) and the separate [multi-store API scope #689](https://github.com/kchavez05/produce-price-tracker/issues/689).

The maintainer removed new store API integration from MVP scope, accepted static estimates for now, and requested separate work covering multiple store APIs rather than only King Soopers/Kroger. A follow-up clarification explicitly selected: **Defer new integration; preserve existing behavior**.

## Effective release scope

- v1.6.2 delivers barcode entry/review/confirmation and shared static/unpriced pantry-staple estimates. Existing reviewed static values and supported identity/unit boundaries remain intact. Missing values remain unpriced and incomplete estimates remain visible.
- Current recipe totals, saved-recipe reevaluation and shopping reuse the shared evaluator. A static estimate is not an observed shelf price or full-package checkout total. Pantry Yes/No, optional quantity/date semantics, pinned choices and owner-bound persistence remain intact.
- New live staple-price adapters, real-source admissions, provider permissions and meaningful observed coverage move from v1.6.2 to unscheduled multi-store work #689. #651 and #652 stay open in Backlog with their existing research preserved. Their previous provider blockers no longer block MVP release.
- #650 retains its merged evaluator/shared UI and requires production verification of static/unpriced behavior. Its real-observation acceptance belongs to the deferred integration work.
- Existing released market discovery, store/circular connectors, market offer scoring and historical data behavior are preserved. This amendment changes no connector code, credential configuration, hosted flag, schema or stored data.
- Barcode USDA lookup, camera lifecycle/privacy, regional abuse controls, artifact integrity, device/account/accessibility acceptance, production verification and the normal release workflow remain required. #649's deferred manual cases are not waived. This decision does not authorize activation or publication.

## Deferred multi-store scope

The [planning scope](../specs/multi-store-api-pricing.md) covers multiple independent retail API providers. King Soopers and other banners using the same Kroger API count as one provider. Provider selection, access, display/derived-cost/comparison permissions, currency and purchase conditions, retention, attribution, budgets, exact admissions and rollout must be qualified separately. No API access, paid service, partnership or release date is assumed.

The existing Kroger sample and clarification draft remain useful evidence for one candidate. No provider message has been sent by this amendment. The initial 13-identity Kroger proposal does not become a universal product mapping or a multi-provider admission record.

## Precedence and evidence

This amendment supersedes the original v1.6.2 requirement to deliver meaningful live staple-price coverage and the commitment to launch Kroger first. The original approved pricing rules, synthetic vectors, source research and bound `catalog/` qualification packets remain historical evidence with unchanged payloads/digests. Reusable qualification/calculation rules do not establish provider facts or permissions.

The [active specification](../specs/v1.6.2-barcode-and-staple-pricing.md), roadmap and live issue acceptance criteria reflect the revised commitment. Production verification and publication remain pending; static estimates are the approved MVP scope, not a claim that this release has shipped.
