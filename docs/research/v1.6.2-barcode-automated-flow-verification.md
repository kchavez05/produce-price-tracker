# Automated barcode/pantry flow verification

The maintainer deferred the physical-device matrix on November 12, 2026 and requested automated barcode/account verification under [#649](https://github.com/kchavez05/produce-price-tracker/issues/649). The [protected camera QA environment and remaining matrix](https://github.com/kchavez05/produce-price-tracker/issues/649#issuecomment-6832612386) remain available. This change adds no runtime behavior or activation.

`tests/smoke/frontend/barcode-pantry-flow.test.ts` connects the actual `VirtualPantry`, `BarcodeEntry`, `BarcodeCamera`, `usePantry`, confirmation, local storage and account queue. Only hardware capture and HTTP responses are synthetic. Six integration cases check:

- Capture requires explicit start, fills digits without lookup or saving, and confirmation persists a guest entry across remount without copying package quantity.
- Cancel leaves stored inventory unchanged and restores focus; reviewed No details, including zero quantity, survive selection and confirmation.
- A failed confirmed account write remains queued through remount and account switching, never replays into another account, and recovers when its original account reconnects.
- Switching account discards an unsaved review. A simulated second-client revision change produces a retained conflict rather than overwriting the newer entry.
- Switching account aborts an outstanding lookup; its late valid response cannot replace or cancel a newer lookup for the new owner or create inventory/queue entries.
- A server session change before the UI account refreshes hides the old pantry/review, stops replay and preserves the original owner's pending confirmation.

The suite runs in the existing Tier 2 `npm run test:smoke` gate, without provider credentials or real account/data writes. The in-memory HTTP model validates caller owner against a separate synthetic server session and uses the real mutation evaluator. It is not evidence of Google OAuth, Supabase authentication/RLS, deployed persistence, real second-client synchronization, physical iPhone Safari/Android Chrome capture or mobile accessibility. Existing unit/backend tests retain their separate coverage; these connected checks do not replace #649's unrun release gates.

Validation receipts and review findings are recorded on [PR #687](https://github.com/kchavez05/produce-price-tracker/pull/687); its [checks](https://github.com/kchavez05/produce-price-tracker/pull/687/checks) retain hosted CI evidence. Local checks include typecheck, source lint, explicit lint of the new test, the full unit and smoke suites, and production build. The initial unconstrained unit run timed out during PGlite initialization; the complete rerun used `npm run test:unit -- --maxWorkers=4`. The tests wait on observable state rather than a fixed number of timer ticks and restore their visibility override. No deployed mobile/account acceptance is claimed.
