## Artifact and deployment procedure

The current pin uses the [losslessly compacted artifact](v1.6.2-barcode-compaction.md), 60,895,232 bytes, with all original logical rows/fields retained. `deployment/barcode-artifact.json` pins the exact already-built artifact and manifest independently of the files supplied by the operator. It retains the approved packet/mapping/source digests, source snapshot date, counts and artifact fingerprint. A refresh requires a reviewed pin update plus the original source/mapping qualification; do not replace this pin with a request-controlled hash. Product publication dates remain visible separately from the October 29, 2026 snapshot and November 10 build time. USDA FoodData Central remains the attributed discovery source; this is last-known product information, not current shelf availability or dietary certification.

From a clean reviewed commit, prepare a new directory outside the checkout:

```sh
npm run barcode:prepare-deployment -- /operator/finalized-artifact /tmp/pantrybot-barcode-preview
```

The script archives only committed HEAD, then copies only `index.sqlite` and `manifest.json`. Extra audit databases, raw CSVs, untracked files, local environments, private databases and credentials are not copied. Existing destinations, repository-nested output, symlink artifact files, changed sizes or changed digests are rejected. Copied artifacts are made read-only and reverified. Failed preparation leaves an incomplete new directory to inspect/discard; it never replaces a deployed bundle.

The prepared bundle's Vercel build command checks both exact hashes, the approved mappings and a known lookup with the real Node SQLite reader, plus a rejected write through a read-only connection, before running the normal Next.js build. Ordinary Git/CI builds continue to work without the ignored artifact; they are not artifact delivery evidence.

Inspect upload inputs before deploying. Use the existing authenticated CLI session; do not place tokens in arguments or files:
