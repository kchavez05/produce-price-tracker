# Lossless barcode artifact compaction (#648)

The November 12 startup investigation measured roughly 1.1–1.7 seconds inside first index initialization under parallel requests. Full integrity verification reads the complete file before SQLite opens. This offline repack reduces those bytes without changing lookup coverage, reviewed mappings or the two-second client deadline. It is an implementation of the approved immutable SQLite delivery contract, not a new source, refresh, paid service or public activation.

## Storage and equivalence

The original 115,613,696-byte artifact is retained unchanged. Repeated product labels/dates move into an integer-keyed dictionary. Clustered product/outcome tables avoid duplicate key indexes; read-only `products` and `outcomes` views expose the same columns, original strings and SQLite value types to the unchanged reader. Original barcode strings, leading zeros, FDC IDs, all revision outcomes, source dates and the 16 exact mappings are preserved. Key filtering still uses the product primary key, followed by dictionary primary-key joins. SQLite documents [clustered tables](https://www.sqlite.org/withoutrowid.html) and [read-only views](https://www.sqlite.org/lang_createview.html).

The finalized repack is **60,895,232 bytes**, a 47.3% reduction. The converter streams canonical ordered logical rows from both files and rejects any column, count, value/type or multiplicity difference before writing a finalized manifest. All 432,347 product rows, 423,460 outcome keys, 16 mappings and the metadata row matched. It also runs SQLite integrity/foreign-key checks and rechecks the original pinned pair after conversion. Complete logical fingerprints are retained in the new manifest/pin; no source product values enter diagnostics.

`deployment/barcode-artifact-v1.json` preserves the original independent artifact/manifest pin. Current `deployment/barcode-artifact.json` pins the repack and its manifest, retaining the same packet, mapping and source fingerprints and linking the source artifact digest. The original bound packet and catalog provenance are unchanged. `builtAtIso` retains the original source artifact's build time; `storageLayout`, parent digest and logical fingerprints identify physical repacking, not fresher product data.

## Operator procedure

Use the retained, exactly pinned original pair from the original-source build. The converter rejects changed input even if its supplied manifest has been rewritten. It opens input read-only/immutable and refuses SQLite sidecars, rejects symlink files, refuses existing or nested output directories and never replaces an active index.

```sh
python3 -B scripts/compact-fdc-barcode-index.py \
  --input /operator/original-barcode-artifact \
  --output /new/operator/compacted-barcode-artifact
npm run barcode:prepare-deployment -- \
  /new/operator/compacted-barcode-artifact /tmp/new-barcode-preview
```

Retain the conversion receipt and both original/repacked pairs externally. A failure leaves a new incomplete output directory to inspect/discard; only a completed pair that matches the current independent pin may be packaged. The recorded conversion uses Python SQLite 3.48.0. Repeated conversion with that version is byte reproducible. The production CLI requires the recorded SQLite version and compares the complete output manifest, logical receipts and both file digests with the current independent pin before finalizing. Other SQLite builds may pack pages differently; a mismatch requires reviewed build/pin evidence, never replacing a pin with a caller-supplied digest. The existing original-source builder remains available for the original format; its historical receipt is not silently rewritten.

No binary is committed or copied to `public/`. Only the current pinned pair enters the prepared deployment. For source rollback, create a branch from latest develop, revert the compaction squash commit recorded on #648, and open a PR to develop with the normal checks and completed Claude review. Reverting the complete change restores the pre-repack source, tests and current pin together (baseline a2abab5); do not hand-edit only the pin. After the reviewed rollback merges, prepare the retained original pair with that restored source and deploy a protected Preview for acceptance. The previous Ready protected deployment is also available as a deployment rollback target. Do not overwrite a deployed file in place. This does not waive any latency gate associated with that older artifact.

## Verification and rollout limits

The real current reader verified the repacked hash and returned the approved olive-oil suggestion locally with approximately 129ms initialization. Synthetic tests cover full logical equivalence (including Unicode/newlines/empty strings and held outcomes), all 16 runtime suggestions, indexed view lookup, read-only write rejection, byte reproducibility, input immutability, source corruption and overwrite/symlink/nesting refusal. These are local/build receipts. Hosted first/parallel latency, complete deployed size and production readiness require separate evidence; the prior two-second failure remains open until requalification supports acceptance. Regional ingress follows the approved [BQ-02 amendment](v1.6.2-barcode-regional-limit-amendment.md). Public lookup/camera remain off, and privacy/device/production gates remain.
