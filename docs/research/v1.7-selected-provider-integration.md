## Adapter contract

No new SDK/gateway or provider failover is introduced. Runtime selection uses only server-side `OPENAI_API_KEY`, never request credentials. The retained Gemini adapter is compatibility/reference code, not an automatic fallback. No key retains standard deterministic suggestions and manual pantry entry.

Recipe requests use `/v1/responses`, `gpt-6.1-terra`, low reasoning, Standard/default service tier, no tools, `store:false`, foreground execution and one generation attempt. The adapter wraps the real application array as `{dishes:[...]}`, recursively disallows extra schema properties and requires all declared fields. Optional declared fields are requested explicitly (rather than introducing nullable values into the app contract). It unwraps only that envelope; existing local schema/catalog/servings validation, app-owned IDs/metadata, ownership fences and authoritative pricing still apply. Unknown ingredients retain the application's explicit `unmapped:` representation, not the spike's smaller schema.

The complete system/input/schema is preflighted with `/v1/responses/input_tokens`; invalid or excessive counts stop generation. Request JSON is also capped at 200,000 UTF-8 bytes. Responses are read with a 1,500,000-byte limit, and generated text with the existing 256,000-character limit. Non-completed/refused/tool-call output, unexpected model/tier, missing usage and usage over the accepted bounds fail closed. Cancellation is propagated through preflight and generation. The shared recipe deadline remains 45 seconds; `max_output_tokens=6000` includes reasoning output. Native fetch makes no application retry and rejects redirects.

Speech uses `/v1/audio/transcriptions`, `gpt-transcribe`, JSON response format and one canonical PCM16 mono 16kHz WAV of 0.25–30 seconds, validated again at the adapter boundary. At most 8,000 transcript characters enter `gpt-6-luna` extraction with the real cooking catalog. Extraction uses strict structured output, no tools/retries, `store:false`, low reasoning and default tier. The shared pipeline deadline is 60 seconds. A single prior durable reservation covers transcription and extraction. Empty transcription returns an UNCLEAR draft without extraction. Nothing mutates inventory until the existing editable, owner-bound confirmation flow.

## Provider data treatment

[OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data), checked November 16, state API data is not used for training by default. The endpoint table lists no abuse-monitoring/application-state retention for `/v1/audio/transcriptions`. `/v1/responses` text has standard abuse-monitoring retention up to 30 days; `store:false` avoids ordinary stored-response state but does not establish Zero Data Retention. Prompt caching may retain application state for up to 24 hours. Account-specific terms, opt-ins and any special retention regime still require verification; no ZDR/region claim is made.

PantryBot retains raw audio/transcripts only in request/review memory, does not log them, and persists only explicit pantry confirmations through the existing flow. The speech screen and privacy page disclose recording/transcript processing by OpenAI. The usage ledger stores no prompts, audio, transcripts or generated output. Users should not include unrelated personal information in recipe notes or recordings.
