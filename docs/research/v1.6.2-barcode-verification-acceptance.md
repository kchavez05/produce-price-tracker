# v1.6.2 reduced pre-release barcode verification acceptance

Accepted by the maintainer November 12, 2026. Primary record: [#649 report and decision](https://github.com/kchavez05/produce-price-tracker/issues/649#issuecomment-6834524807), linked from release parent #645 and production/release issue #653.

The maintainer reported a couple of iOS Safari smoke tests of barcode scanning and typed/key entry, declined to run the full original matrix for now, and explicitly considered #649 unblocked and ready for release. This is an acceptance of reduced **pre-release** verification, not evidence that the original full matrix passed.

## Evidence boundaries

- iOS Safari scanning and typed/key entry are maintainer-reported evidence. The agent did not independently observe those tests.
- Device model, iOS/Safari versions, deployment URL/source head, individual assertions and screenshots were not supplied. The tests are not automatically attributed to the earlier camera QA deployment.
- Android Chrome, the full permission/lifecycle/accessibility matrix, fresh OAuth and second-client/account-isolation/persistence/conflict/retry flows, and cleanup were not individually reported as tested. The maintainer accepts that unrun remainder as non-blocking for pre-release readiness. No unreported case is marked Pass.
- Existing desktop Preview, unit, smoke and regression receipts retain their own source, date and limits. The six connected smoke cases use synthetic hardware/HTTP boundaries and do not establish real OAuth, Supabase RLS or physical-device behavior.
- No new hosted users or inventory were created by setup/automation. This user report does not supply additional account/data or cleanup evidence, so none is inferred.

## Effect and remaining gates

#649 is open in Awaiting release with the blocked label removed. #653 is ready for release preparation. This later decision supersedes earlier statements that the full #649 pre-release device/account matrix must run before proceeding, including that aspect of the earlier static-pricing scope amendment and original specification. It changes neither barcode implementation/security requirements nor existing source qualification records.

Record the exception in release notes. Normal CI/Claude review, pinned artifact delivery, production-scoped ingress enforcement, approved activation, applicable exact production acceptance and release/tag publication remain required under #653. This exception does not authorize treating an artifact-free build, disabled endpoint or Preview as verified public production availability. No production settings or publication changed when this decision was recorded.
