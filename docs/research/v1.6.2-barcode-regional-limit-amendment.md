## Amended contract

BQ-02 accepts shared enforcement of **30 lookup POST requests per IP per 60-second fixed window per Vercel edge region**, including invalid and failing requests. Excess requests receive platform HTTP 429. The client must retain recoverable throttling, window-reset retry and manual entry. A global shared counter is no longer required by this amended rate-limit contract.

The limit applies independently in each edge region. Traffic using the same key in N regions can admit approximately 30 × N requests per aligned window; this is not a global 30-request ceiling. Fixed-window boundary bursts remain possible. These are accepted bounds of the existing control, not a claim that multi-region counting was tested. Vercel documents the [regional counter behavior](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting).

The published qualification rule `rule_pantry_bot_barcode_preview_limit_vttWCQ` matches route `/api/pantry/barcode-lookup` AND method POST AND environment Preview, uses IP keys, and returns 429 after 30 requests in 60 seconds. Existing dated [deployment receipts](v1.6.2-barcode-deployment.md#native-safari-qualification--november-12-2026) verify regional threshold/reset, rotated-IP-header resistance, parallel counting, sharing across deployments and bounded route variants. These receipts satisfy the amended regional ingress qualification item for the recorded protected Previews; production enforcement and acceptance remain separate gates.
