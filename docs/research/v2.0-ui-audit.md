# v2.0 UI Audit — Current Homepage (v1.6.x)

Status: Draft research for [v2.0 M0](../specs/v2.0-ui-redesign.md). Observed 2026-11-11 on `develop` (`ab86828`) running locally with no API keys (Pantry observations come from the Vercel preview of the same commit with the pantry flag on), at a phone-width emulated viewport (393x852 requested; the page reported a layout width of about 557px, so treat pixel metrics as approximate). Code facts come from `src/components/MealPrepDashboard.tsx` and `src/app/page.tsx`.

## 2. Findings

### Navigation and information architecture
1. **Virtual Pantry is a toggled panel in the page flow** (`showFreezerModal`), opened from a header "Freezer (n)" button and rendered above the tab content. It is not a destination. The button is still labelled "Freezer" although the feature is now the Virtual Pantry.
2. **The tab bar is numbered and wraps.** Four full-width pills stack vertically on a phone (labels like "3. Shopping List & Cart Bridge"), pushing content below the first screen. The numbering encodes a workflow order but not a navigation model.
3. **Tabs map imperfectly to the three workflows.** Value Board and Radar are both price/shopping intelligence; Shopping List is the output of Shop; Meal Prep is Plan. Pantry has no tab. Pantry data appears as "Have at home" buttons on Value Board cards and as freezer/pantry arbitrage in the alert strip.
4. **Global controls are mixed with workflow controls.** ZIP, store filters and the ad-cycle notice sit in the sticky header and apply to everything, while dietary/macro/vessel filters (preferences) live inside Meal Prep only.
5. **Several unrelated drawers hang off the header and the dashboard**: weekly cron/push preview, optional API key (removed by v1.7), ZIP switcher, My Stores.

### Mobile ergonomics
6. **Length:** Value Board measured ~23,000px tall (about 27 phone screens) in one scroll; the other tabs ~5,400–6,200px. There is no sectioning, sticky sub-navigation, or pagination on the leaderboard.
7. **Touch targets:** a scripted count found roughly 100 interactive elements on Value Board and about 90 on Shopping List smaller than 44x44px in at least one dimension (approximate; not all are primary controls). Chips, icon buttons and card actions are the likely offenders.
8. **Top of screen:** on first load the visible area is header, store chips, a long status notice, and four tab pills before any price content.
9. **No horizontal overflow** was detected at phone width. The store chip row scrolls horizontally within itself.
10. **Text density:** the ad-cycle notice is a multi-line paragraph of operational status (refresh times, source availability) placed above the content for every user.

### Visual system
11. **No tokens or theme.** Colors are hardcoded Tailwind classes; each region uses its own palette (dark indigo, dark emerald, amber, sky, violet gradients). Cards use many border/gradient/shadow styles.
12. **No dark mode** (no `dark:` classes), and heavy use of dark gradient panels in an otherwise light UI.
13. **Heading hierarchy:** one `h1`; section headings jump between `h2` and `h3` with differing sizes per region.

### Accessibility (code-level, not a full audit)
14. The dashboard has only three lines with `aria-` or `role=` attributes, and there are no automated a11y checks. The tab bar is buttons, not a `tablist`. Modals/drawers use focus return on close in at least the pantry panel (`pantryTrigger.current?.focus()`), which is a good pattern to preserve.
15. Print and forced-colors CSS exist and must survive the redesign (printable shopping slip).

### Test and maintainability
16. Logic tests exist (Vitest). jsdom component tests exist only for `VirtualPantry`, `BarcodeEntry` and `BarcodeCamera` (hand-rolled `react-dom/client` plus `act`, no React Testing Library). **`MealPrepDashboard`, `AccountModal` and the Data Explorer have no component tests, and there are no browser, visual or accessibility tests.** Decomposition (M3) therefore needs a behavior-preserving test harness first (M2). *(Corrected 2026-11-12: this item originally said there were no component tests at all.)*
17. `page.tsx` is a server component that builds the whole dashboard payload and passes it as props, plus feature flags (`PANTRYBOT_PANTRY_ENABLED`, barcode, camera). A modular split needs to decide whether each module loads its own data.
18. **Virtual Pantry panel (flag on, guest, empty):** opening it inserts a ~616px-tall panel in the page flow between the status notice and the tab bar (starting ~375px down), which pushes the tab bar to ~1,014px, beyond the first phone screen. The header switches from sticky to `relative` while the panel is open, so global controls scroll away. The panel holds search, four optional shortcut chips, a "Saved on this device. Sign in for cross-device recovery." status, a "Review older local inventory" action and an "Also show ingredients marked No" toggle; all 8 of its controls measured under 44px in at least one dimension. Accessible names are current ("Open Virtual Pantry", "Update explicit pantry availability"). A populated pantry, search results and conflict states will be taller. This confirms Pantry needs to be its own destination.

## 3. Coverage gaps in this audit

- **Virtual Pantry (observed on a Vercel preview with the pantry flag on, 2026-11-11, guest state, empty inventory):** see finding 18. Local keyless runs and the earlier barcode-fix preview have the flag off and only show the legacy "Virtual Freezer" fallback drawer. Verified captures also exist in `docs/research/assets/` (v1.6.1).
- Signed-in states, the account drawer, and the AI chef flow were not captured.
- No iPad-width capture yet; iPad review happens against mockups.
- No analytics are available, so "most-used" claims are unproven. Ask the owner which flows matter most.

## 4. Implications for v2.0

- Adopt the Shop / Pantry / Plan split; see [v2.0 flows and navigation](v2.0-flows-and-navigation.md).
- Promote global context (ZIP, stores) out of the page header into a compact context control; move preferences (dietary, macros, vessel, servings) into a shared preferences surface that Plan reads.
- Replace pill tabs with platform-native navigation (bottom tabs on iPhone, sidebar on iPad).
- Break Value Board into scannable sections (alerts, leaderboard with filters) with paging or virtualization.
- Design for the features still landing through v1.7 (barcode, dynamic staple pricing, speech, sign-in for AI), which this audit does not cover because they are not yet in the UI; see [spec section 3b](../specs/v2.0-ui-redesign.md).
- Establish tokens, one card system, and tap-target and contrast standards before screen work.
